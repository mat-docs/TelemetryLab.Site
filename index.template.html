Why not just Kafka and a database

Telemetry is not generic time-series data

You can build a pipeline out of Kafka, InfluxDB and Grafana. Most teams do, and then rebuild sessions, units and sample rates by hand, every time. That is what this platform already has, and what the course teaches.

A bare Kafka topicATLAS Open Streaming
a channel a field name an identity with units, sample rate, valid range and display format — carried in-band
a session a time window you agree on a first-class lifecycle, with its own configuration attached
multi-rate your problem modelled — periodic, row and synchro forms
laps & events a table you maintain separately timestamped markers on the stream
a late joiner your problem configuration is explicit, so you know what you missed

The usual symptom of not having this is a chart that has quietly been in the wrong units since somebody swapped a sensor eighteen months ago.

Questions

Before you start

The rest are on the course page.

What is the ATLAS Telemetry Lab?

Free coding exercises that teach how a real-time telemetry pipeline works, by making you run one and change it. You copy a repository, open it in a browser IDE, and a broker, a streaming API and a simulated car start up. You edit code; a bot runs it against the pipeline and reports what happened.

Do I need an ATLAS licence?

Not for course 01. The three images it runs — Apache Kafka, the ATLAS Stream API and the Key Generator — are public on Docker Hub and pull with no account or licence key; that is how the automated validation runs every time. ATLAS Viewer, the commercial desktop application, is not used. If a later course needs a licensed component, its own page will say so.

What does it cost?

We charge nothing. The compute is GitHub's and comes out of your own allowance: Actions is unlimited on public repositories and 2,000 minutes a month on private ones, and Codespaces gives personal accounts 120 core-hours a month free, or 180 on Pro. On the 2-core machine this uses, 120 core-hours is 60 hours of run time.

How long does course 01 take?

We do not know yet, and any figure we gave you would be invented. Nobody outside the team has run it start to finish. What is measured: four modules, a Codespace that takes about three and a half minutes to become usable, and a validation run of roughly two minutes each time you submit. We will publish a real number when we have one.

How is my work marked?

A GitHub Actions workflow in your own repository runs the whole pipeline against what you wrote and comments on your pull request. It grades behaviour, not shape: it never looks for a particular line of code, it runs the thing and checks what it did. Solve a module a different way and it still passes.

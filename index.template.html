Why not just Kafka and a database

Telemetry is not generic time-series data.

You can build a pipeline out of Kafka, InfluxDB and Grafana. Most teams do. What you then build by hand, and keep building, is everything that makes telemetry different.

A bare Kafka topicATLAS Open Streaming
a channel a field name an identity with units, sample rate, valid range and display format — carried in-band
a session a time window you agree on a first-class lifecycle, with its own configuration attached
multi-rate your problem modelled — periodic, row and synchro forms
laps & events a table you maintain separately timestamped markers on the stream
a late joiner your problem configuration is explicit, so you know what you missed

The usual symptom of not having this is a chart that has quietly been in the wrong units since somebody swapped a sensor eighteen months ago.

Questions

Before you start

What is ATLAS Open Streaming?

A real-time telemetry platform from Motion Applied. A producer sends data over gRPC to a Stream API, which registers the session, holds the configuration describing each channel, and writes to Kafka. Any number of consumers read from there. The images are published publicly on Docker Hub and need no licence.

Do I need an ATLAS licence?

No. Every component the courses use — the Stream API, the Key Generator, Kafka — is published publicly and free to run. ATLAS Viewer, the commercial desktop analysis application, is a separate licensed product, and nothing in any course requires it.

What does it cost?

Nothing. GitHub Actions is free on public repositories, and Codespaces draws on your own allowance — 120 core-hours a month on a free account, 180 on Pro, and students get Pro through the GitHub Education pack. Course one uses well under one hour of that.

What do I need installed?

Nothing, if you use a Codespace — it builds with Docker, Python 3.12 and Node 22 already in it, and the container images pre-pulled. To run on your own machine instead you need those three, and the same docker compose up works.

How is my work marked?

A bot in your own repository runs the whole pipeline against what you wrote and comments on your pull request. It grades behaviour, not shape: it never checks for a particular line of code, it runs the thing and checks what it did. Solve a module differently and it still passes.

Do I need to know anything about motorsport?

No. The simulated car is a convenient source of realistic multi-rate data with laps and events in it. The concepts — sessions, parameter definitions, contiguous timestamps, markers — are the same whether the data comes from a race car, a UAV, or a test rig.

Is this only useful for motorsport?

No. The problem it addresses — a stream where channels carry their own identity, units and rate, and sessions have a real lifecycle — turns up in robotics, aerospace test, automotive test and any rig logging hundreds of channels at mixed rates.

Can I use a language other than Python or JavaScript?

Yes, from Module 4 onward. The producer and reference consumer ship in Python and JavaScript, but the protocol is protobuf over Kafka and the definitions are public. Module 4 grades what your consumer reported against what the producer recorded sending, in any language.

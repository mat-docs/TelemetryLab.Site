What it covers

Four things a bare Kafka topic has no concept of.

You can move numbers with Kafka alone. What you cannot do is say what a number is — its units, its valid range, how fast it arrives, which session it belongs to, and what happened during that session. Each module here is one of those, taught by making you build it and then breaking it.

How it runs

You work in your own repository.

Take a copy of the lab from the template — it becomes a repository you own, with the validation bot already in it. Open a Codespace on it, or clone it and run locally if you would rather.

Each module asks for a change. Run lab check to grade it on your own machine in seconds, then lab submit to branch, push and open a pull request. The bot runs the whole pipeline again on a clean machine, comments with what it found, and on a pass advances you to the next module and merges.

lab check runs the identical code the bot runs, so a pass locally is a pass in CI. There is no reason to ever push a guess.

Prerequisites

What you should already know.

Enough Python to edit a script and enough command line to run docker compose up. Module 4 asks you to write a consumer, in any language you like — a reference implementation in JavaScript is in the repository to read if you want it.

You do not need Kafka experience, motorsport knowledge, or any hardware. The car is simulated and the data is synthetic.
